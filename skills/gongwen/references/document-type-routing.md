# 法定公文文种路由规则

本规则用于在起草正文前确定15种法定公文的文种。不得只根据用户拟定标题的末尾词语判断文种，也不得因为用户先写了某个文种名称就跳过适用性核验。

## 规则优先级

1. 用户本次提供的事实、来文和明确用途。
2. 用户上传或内部专属文件库中的现行制度、单位权限和模板。
3. 《党政机关公文处理工作条例》及 GB/T 9704—2012 等正式规范。
4. 本规则中的工程化判断方法。

社区项目只用于补充工作流、模板和检查方法，不作为政策依据。参考来源：

- `Rimagination/gongwen-draft`：15文种路由、易混文种边界、审核清单。
- `KaguraNanaga/official-document-writing-skill`：请示、通知、函、报告、纪要等高频文种的场景化结构与检查方法。

## 六步判断

依次判断，不得颠倒：

1. **目的**：是作出决定、部署执行、请求批准、报告情况、答复来文、公开发布，还是记录会议？
2. **行文关系**：收文方是上级、下级、不相隶属机关、社会公众、会议参与者，还是人大审议机关？
3. **期望动作**：需要批准/指示、执行、知悉、遵守、函复、审议，还是仅归档记录？
4. **范围**：是明确主送机关、特定区域或人群、广泛社会公众，还是会议内部？
5. **权限与程序**：是否有发布命令（令）或提出议案的法定权限；是否经过会议讨论并表决通过？
6. **来文类型**：答复时必须识别原来文是请示还是函；下级请示用批复，不相隶属机关来函用函（复函）。

若仍有两个以上合理文种，一次只追问一个最能改变结果的问题。文种确定前不得生成 Word。

## 15文种路由矩阵

| 文种 | 核心用途 | 关键条件 | 常见排除项 |
| --- | --- | --- | --- |
| 决议 | 会议讨论并表决通过重大事项 | 必须有明确会议及通过事实 | 未经会议通过不能写成决议；机关直接部署通常用决定或通知 |
| 决定 | 机关对重要事项作出决策部署、奖惩、变更或撤销 | 发文机关直接作出决定 | 一般性工作安排优先通知；会议表决通过重大事项优先决议 |
| 命令（令） | 公布行政法规规章、重大强制措施、嘉奖有关单位和人员 | 发文主体具有相应法定权限 | 权限不明确时不得模拟命令，改核决定或通知 |
| 公报 | 权威公布重要决定、重大事项、会议成果或统计结果 | 强调权威、系统发布成果或结果 | 单一遵守事项不宜用公报；一般公开事项核对公告或通告 |
| 公告 | 向国内外或广泛公众宣布重要事项、法定事项 | 公开范围广，事项具有重要性或法定性 | 面向特定区域、人群的遵守事项用通告；内部部署用通知 |
| 通告 | 在一定范围公布应当遵守或周知的事项 | 对象范围可界定，常含期限、区域、行为要求 | 有明确机关主送并要求内部执行时优先通知 |
| 意见 | 对重要问题提出见解和处理办法 | 重在原则、政策性指导和方法 | 具体会议、培训、报送安排优先通知；正式作出重大决定优先决定 |
| 通知 | 发布、传达、转发、批转，部署具体工作或告知事项 | 对象明确，要求执行或知悉，安排具体 | 不用于表扬批评；不用于向上请求批准 |
| 通报 | 表彰先进、批评错误、传达重要精神或告知重要情况 | 重在事实、评价、警示或推广 | 单纯向上汇报用报告；纯部署工作用通知 |
| 报告 | 向上级汇报工作、反映情况、回复询问 | 上行，不要求批准或指示 | 不得夹带请示事项；期待批复时应使用请示 |
| 请示 | 向有隶属关系的上级机关请求指示或批准 | 上行、一文一事、主送一个上级机关、期待批复，原则上不得越级 | 向不相隶属主管部门请求审批用函；仅报告情况用报告 |
| 批复 | 答复下级机关请示 | 必须对应具体请示来文 | 答复平行机关来函用函；无请示来文不得凭空写批复 |
| 议案 | 有权主体按法定程序提请本级人大或其常委会审议 | 提案主体、审议机关及权限均明确 | 一般机关向上级请求批准不得用议案 |
| 函 | 不相隶属机关之间商洽、询问、答复、请求支持或审批 | 平行关系或无隶属关系，可为商洽函、询问函、请批函、答复函 | 向直接上级请求批准用请示；答复下级请示用批复 |
| 纪要 | 记载会议主要情况和议定事项 | 基于真实会议事实和形成的共识、议定事项 | 尚未召开会议或未形成议定事项时不能编造纪要 |

## 易混文种硬边界

### 请示与报告

- 出现“请批准、请审定、请指示、是否同意”等期待上级作出答复的动作，选择请示。
- 仅汇报进展、问题、成效或答复上级询问，选择报告。
- 报告正文不得在结尾或措施中夹带审批请求。

### 请示与函

- 向有隶属关系的上级机关请求指示或批准，选择请示；不把“直接上级”误写成绝对条件，但应核验是否存在越级请示问题。
- 向不相隶属但有主管审批权限的机关请求批准，选择函（请批函），不得使用请示。

### 批复与复函

- 回复下级机关的请示，选择批复，并对应来文标题或文号。
- 回复不相隶属机关的函，仍选择函（答复函/复函），不得使用批复。

### 决议与决定

- 明确经过会议讨论、表决并通过的重大事项，选择决议，并保留会议通过信息。
- 发文机关直接对事项作出决策、部署、奖惩、变更或撤销，选择决定。

### 决定与通知

- 形成重要、稳定、具有决策性质的处理结论，选择决定。
- 传达事项、部署常规工作、安排会议培训或要求报送材料，选择通知。

### 公告与通告

- 面向国内外或不特定广泛公众发布重要、法定事项，选择公告。
- 面向特定地域、行业、人群公布应当遵守或周知的事项，选择通告。

### 公报与公告

- 系统、权威公布会议成果、重要决定、重大事项或统计结果，选择公报。
- 宣告单项重要或法定事项，且不以系统披露成果为主，选择公告。

### 通报与报告

- 向一定范围传达事实并作出评价、警示、表扬或推广，选择通报。
- 向上级客观汇报工作或情况，不面向下级作评价和部署，选择报告。

### 通知与意见

- 重点是具体任务、时间、地点、对象、责任和执行要求，选择通知。
- 重点是对重要问题提出原则性、政策性见解和处理办法，选择意见。

## 输入不足与冲突处理

- 用户未指定文种：按本规则推荐文种，并说明关键理由。
- 用户指定文种且与用途一致：保留用户文种。
- 用户指定文种与用途、行文关系、来文类型或权限冲突：不得静默改文种，也不得继续生成；一次追问一个最高影响问题，确认后再生成。
- 命令（令）或议案权限未确认、决议没有会议表决通过事实、批复没有对应请示、纪要没有真实会议召开事实或议定事项时，均视为阻断问题。
- 标题后缀与实际用途冲突时，以事实和行文关系为判断依据，并提示用户修正标题。
