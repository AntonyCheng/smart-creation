# 智能公文生成

交付一个Word草稿、对话审核单和一个可点击下载链接。草稿不代表审批、签发或用印完成。

## 边界与依据

- 本次明确资料优先于单位文件库；两者冲突须展示差异并请用户确认，不静默择一或改造事实。
- 国标原件 `references/党政机关公文格式.pdf` 控制格式，`references/gbt9704-detailed.md` 是执行摘要，`references/gbt9704.md` 是索引。文种适用性与办理权限不由格式标准单独决定；不得虚构条例条款号或审批权限。
- 不生成印章、签名图片、虚构政策、成绩、数字或审批状态。“需要盖章”只选择待用印文字版式，不画章；“不生成印章图片”不等于已经确认正式公文免章。用印方式不明确时只追问这一项。
- 发文机关标志、标题机关称谓、发文机关署名、印发机关分别保留，不强制同名。若明确的发文主体与署名存在实质冲突，提示确认，不自行换成办公室。
- 不把用户输入中的“XX”当作真实机构或自行替换。演示事实须由用户明确提供/确认；“用于演示”不是自行编造其他细节的授权。

## 工作流

### 1. 定义任务和文种

只判断文种或只审校文本时，不生成文件。新稿及正文改写先读 `references/document-type-routing.md`、`references/document-types.md` 和 `references/document-subtypes.md`，填写 `type_selection`、`document_type`、`document_subtype`、`direction`、`layout_profile`，按实际行文关系确定。

报告不得夹带请示；请示一文一事、主送唯一；决议须有会议讨论通过事实；纪要须有会议及议定事项；批复须对应下级请示、复函对应不相隶属机关来函；命令和议案须核实主体权限。缺少改变文种或合法成文的关键信息时，一次只追问一项，不填写true绕过核验。

### 2. 留存原始资料后组稿

保留本次用户原始请求和相关资料，按 `references/source-evidence.md` 建立依据追溯。原文、来源文件名和位置必须可核对；不得把自行拟写的正文或content_facts反称为用户原始资料。工作资料放在员工工作区，不放在Skill目录。

可以整理层次、规范表达并进行忠实的同义改写；不得新增原材料没有的政策、事实、机构人员、日期数字、已完成成果及执行安排。逐项将正文中的事实与原资料核对，尤其核对否定、拟实施/已完成、责任主体和数字单位。不得擅加“全天培训”“提前15分钟签到”“全面覆盖”“显著提升”等。材料不足时一次追问一项或使用明确占位，不得为满足篇幅补造内容。证据字段中的verified只记录核对动作，不证明资料真实；脚本检查也不能替代这一内容审查。

答复和政策资料读 `references/source-evidence.md`；多份Word/PDF/Excel材料读 `references/material-workflow.md`；篇幅/修订模式读 `references/writing-modes.md`；文字审校读 `references/language-review.md` 和 `references/audit-checklist.md`。

### 3. 一次准备最终文件

按 `references/input-schema.md` 写本次唯一输入JSON。新起草/改写设 `content_validation_required: true`、`text_review_required: true`；用户明确字段复制到user_contract用于防止传参改写，但不能拿它证明事实真实。按国标摘要选版式，标题不加粗；长标题必须提供按词意划分的title_lines，拼接后与原标题逐字一致。保留四类版式、署名日期联动、附件和版记规则，版记较长时自动回行、计算整体高度并检查末条线位置。

先确认安装目录与 `runtime.json`，按 `references/runtime-and-delivery.md` 调用：

```text
python3 <Skill绝对目录>/scripts/prepare_draft.py <本次输入JSON绝对路径>
```

脚本一次完成已实现的文种/内容规则检查、生成、结构检查、文件哈希及候选链接；事实语义和来源真实性仍须对照原始材料审核。脚本失败时按具体错误修正资料或输入，最多两次；仍失败则保留文件、报告阻断，不能反复读源码、替换字体或改脚本绕过检查。运行期不修改Skill源码，不安装字体，不扫描无关工作区。

每次输出保存到独立运行子目录，文件名仍为“标题（草稿）.docx”，防止同标题覆盖和旧链接串稿。禁止回传中间JSON、校验单、脚本、PDF或渲染图。

### 4. 验证范围与交付

结构通过不等于实际字体可用。只有使用指定字体的实际逐页渲染且检查每页无缺字、裁切、重叠、异常分页、署名/版记错位，才能说“本文件视觉检查通过”。字体缺失、未知或未渲染时，在审核单写明“仅完成结构检查，视觉合规未验证”；不得写“完全符合国标”或“错误0即全面合规”。

平台支持 `send_channel_file` 时只调用一次，传prepare输出的精确文件路径；成功后直接使用同次prepare输出的候选链接，不再调用多个发送工具/重新生成文件。传送失败可重试一次；仍失败不得声称已交付。其他宿主使用其正式文件附件机制；local路径不能冒充下载URL。环境适配和HTTP验证边界见 `references/runtime-and-delivery.md`。

对话审核单按“阻断问题、重要问题、一般优化、依据追溯、待补要素”输出，区分来源核对、文种规则、结构、视觉、下载五种检查。最后一行放唯一可点击DOCX链接，不能加代码框或反引号。若用户只要链接且存在未通过的重要检查，必须先简短说明，不能隐瞒缺陷。

## 已有Word

只做重排时保留原文，不强制新起草字段；重写事实仍须重新做来源核验。批注、修订、文本框、表格或附件提取不完整时先提示，不能静默丢弃。特殊图表、联合行文、超长版记或复杂混排超出当前脚本验证范围时，不能宣称全面合规，应按原件人工核对后交付。

## 安装与共享

分享完整目录，保留scripts、references、assets/base.docx及元数据；移除缓存、历史输入和生成文件。按 `references/runtime-and-delivery.md` 为新宿主配置runtime.json，不沿用原员工ID，不附带Token或账户数据。本技能包经用户确认附带5份字体，来源记录见assets/fonts/SOURCES.md；使用方可打开字体文件安装到当前用户字体目录，不覆盖不同版本字体。

本地项目安装在 `.agents/skills/intelligent-official-document-generation/`，显示名为“智能公文生成”。首次使用先按 `INSTALL.md` 配置本机输出目录；不要沿用分享者的绝对路径。Codex 项目内可用 `$intelligent-official-document-generation` 调用；其他宿主使用其技能加载机制，不把本地目录伪装成平台技能已安装。

会议通过信息不是二级标题：未提供其他明确依据时按第5.2.2条默认三号仿宋、不附加粗体。生成器将结尾段与附件说明、署名日期关联分页；这不是人工改交付文件的补丁。纪要标志已经含“纪要”时不重复拼接。上述仍需每次对实际输出逐页检查。
